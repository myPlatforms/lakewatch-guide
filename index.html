개요 & 시작
Lakewatch
구성·실습 가이드

워크스페이스에 Lakewatch를 처음 구성하는 관리자 절차(사전 요건 → Preview 켜기 → 환경 만들기 → 접근 제어)와, 가상의 제조사 Signal Dynamics에서 일어난 두 건의 사고를 직접 조사하는 실습을 한 흐름으로 묶었습니다. 데이터소스와 파서, 탐지 규칙, Alert, Genie 분류(트리아지)까지 Lakewatch의 전체 과정을 다룹니다.

ℹ️

공식 문서 기반 한국어 버전
이 사이트는 Lakewatch 공식 문서(AWS (opens in a new tab) · Azure (opens in a new tab))를 기반으로 작성된 한국어 버전입니다. 실제 워크스페이스에서 확인한 화면을 함께 실었습니다. Lakewatch는 Beta (opens in a new tab) 단계라 화면과 동작이 바뀔 수 있으므로, 최신 내용은 공식 문서에서 확인하세요. 본문의 "근거 문서"와 "참조" 링크는 영문 공식 문서로 연결됩니다.

Lakewatch 개요

Lakewatch는 보안 정보 및 이벤트 관리(SIEM) 기능을 레이크하우스에 직접 제공하는 Databricks 기능입니다. 보안 팀이 위협을 탐지하고, 인시던트를 조사하며, 보안 이벤트에 대응하도록 돕습니다.

Lakewatch는 무엇을 하나요?

Lakewatch는 보안 팀에 다음 작업을 한곳에서 수행할 수 있는 환경을 제공합니다.

  • CrowdStrike, Okta, AWS CloudTrail 등의 소스에서 보안 데이터를 수집합니다. API 커넥터, 클라우드 스토리지 경로, 워크스페이스에 있는 기존 테이블을 사용할 수 있습니다.
  • 파서를 사용해 데이터를 표준 필드 집합을 갖춘 거버넌스 적용 테이블로 스키마화합니다. 이를 통해 서로 다른 데이터 소스에서도 동작하는 탐지 규칙과 쿼리를 작성할 수 있습니다.
  • 예약된 일정에 따라 실행되는 SQL 기반 탐지 규칙으로 위협을 탐지합니다.
  • 관련 Signal을 자동으로 묶고 관련 이벤트 및 엔티티와 연결하는 Alert를 통해 인시던트를 조사합니다.
  • Lakewatch UI에서 SQL로 보안 데이터를 직접 쿼리합니다. 시간 범위 필터, 코드 없이 적용하는 세부 조정(refinement), 행 단위 상세 검사를 지원합니다.
  • Genie (opens in a new tab)로 AI 기반 조사를 수행합니다. Lakewatch UI 전반에 내장된 어시스턴트인 Genie Code와 여러 단계에 걸친 심층 조사를 위한 Genie Agents를 사용해 자연어로 쿼리를 작성하고, 탐지 규칙을 만들고, Alert를 분류할 수 있습니다.

작동 방식

Lakewatch는 데이터소스 (opens in a new tab)를 사용해 보안 데이터를 워크스페이스로 가져옵니다. 데이터소스는 수집 방법(원시 데이터를 읽는 방식)과 원시 데이터를 거버넌스 적용 Unity Catalog 테이블로 스키마화하는 하나 이상의 파서를 결합합니다.

  • 원시 데이터: 데이터소스의 수집 방법이 외부 소스에서 읽어 온 가공되지 않은 데이터입니다.
  • 파싱된 테이블: 데이터소스의 파서 (opens in a new tab)가 기록하는 스키마화된 테이블입니다. 각 파서는 로그 소스의 출력 열을 설명하고, Lakewatch가 관리하는 lw_id, lw_meta, lw_observables (opens in a new tab) 열을 추가합니다.

파싱된 데이터는 보안 분석에 바로 사용할 수 있습니다.

  • 탐지 규칙 (opens in a new tab)은 예약된 일정에 따라 파싱된 테이블에 대해 SQL 쿼리를 실행합니다. 규칙의 조건이 일치하면 Signal (opens in a new tab)이 생성됩니다. Signal은 무엇이 탐지되었는지, 언제 발생했는지, 어떤 엔티티가 관련되었는지를 기록한 레코드입니다.
  • Lakewatch는 관련된 Signal을 자동으로 묶어 조사용 Alert (opens in a new tab)를 만듭니다. 분석가는 Alert를 할당하고, 분류하고, 해결될 때까지 추적할 수 있으며, Jira, ServiceNow 또는 Tines로 내보낼 (opens in a new tab) 수 있습니다.
  • 쿼리 페이지 (opens in a new tab)에서 보안 데이터에 대해 SQL 쿼리를 실행하여 임시(ad hoc) 조사를 할 수 있습니다. 시간 범위 필터, 코드 없이 적용하는 세부 조정, 행 단위 상세 검사를 지원합니다.

Lakewatch는 자체 탐지 규칙과 데이터소스도 모니터링하며, 실패하거나 구성 문제가 있으면 시스템 오류 (opens in a new tab)를 엽니다. 시스템 오류는 보안 Alert와 별도로 추적됩니다.

이 절은 공식 문서 Lakewatch 소개 (opens in a new tab)를 우리말로 옮긴 것입니다. 화면은 이 가이드의 실습을 마친 뒤의 Overview 페이지입니다.

비용
실습 환경은 데이터소스 5개와 탐지 규칙 17개를 만듭니다. 데이터소스는 사고를 재생할 때만 수집하고, 탐지 규칙은 켜진 동안 1시간마다 SQL 웨어하우스에서 실행됩니다. 사고 재생 3시간 뒤 자동으로 일시 중지되지만, 실습을 마치면 10단계의 pause를 직접 실행하세요. 운영(production) 워크스페이스가 아니라 개발·샌드박스 워크스페이스에서만 진행하세요.

"화면 확인"의 뜻
날짜가 적힌 단계는 그날 시작한 실습에서 실제 워크스페이스로 절차를 수행하며 화면을 캡처했습니다. 괄호로 제외한 부분은 직접 실행하지 않고 실습 노트북 코드와 실습 자료를 근거로 썼고, 화면 이름이나 결과가 다를 수 있습니다. 각 페이지 위쪽의 "확인 범위" 안내에 어디까지 확인했는지 적었습니다. Genie가 등장하는 8·9단계는 실행할 때마다 답이 달라지므로 한 번의 실행 결과로 읽으세요.

학습 목표

  • Lakewatch를 쓰기 위한 워크스페이스 요건을 확인하고, Preview를 켜서 앱을 연다
  • Custom configuration으로 환경(카탈로그)과 폴더(스키마), 관리자를 정해 Lakewatch 환경을 만든다
  • 권한 그룹으로 데이터소스 담당, 탐지 규칙 담당, Alert 분석 담당의 접근을 나눈다
  • 데이터소스와 파서가 원시 로그를 파싱된 테이블로 바꾸는 과정을 따라간다
  • SQL 탐지 규칙의 조건을 읽고, 과거 데이터로 임계값을 시험한다
  • Alert를 맡아 Genie로 조사하고, 근거와 함께 판정을 남긴다
  • 약한 Signal 세 개를 하나의 상관 탐지 규칙으로 묶는다

사전 지식

  • Databricks 워크스페이스 사용법 (사이드바, Catalog Explorer, 노트북 실행)
  • 기본 SQL (SELECT, GROUP BY, HAVING, 조인)
  • Unity Catalog 기본 (카탈로그·스키마·테이블·권한)

데이터소스, 파서, Signal, Alert 같은 Lakewatch 용어는 용어 정리에 모았습니다. 보안 용어가 낯설다면 실습 전에 먼저 읽어 보세요.

실습 자료

실습 환경은 노트북 한 개로 만듭니다. 탐지 규칙, 파서, 데이터 생성기, 정리 로직이 모두 이 파일 안에 들어 있습니다.

  • signal_dynamics_lab.py: 이 사이트에서는 내려받을 수 없습니다. Databricks 담당 어카운트팀에 요청해 받으세요. 1–4단계(관리자 구성)는 노트북 없이 진행할 수 있습니다.
