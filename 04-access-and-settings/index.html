4. 접근 제어와 기본 설정

4단계 - 접근 제어와 기본 설정

환경을 만든 뒤 Settings에서 관리자와 폴더 권한을 다듬고, 탐지 규칙·데이터소스·Alert의 기본값을 확인합니다. 이어서 데이터를 넣기 전에 Content library, Parsers, Add datasource 화면을 둘러봅니다.

근거 문서: Lakewatch 설정 구성 (opens in a new tab), Lakewatch 접근 제어 설정 (opens in a new tab)

학습 목표

  1. Settings의 다섯 탭에서 각각 무엇을 설정하는지 설명한다
  2. 권한 그룹 다섯 가지가 어떤 권한을 주는지 구분한다
  3. 역할에 맞춰 폴더 권한을 나누는 예시 구성을 적용한다
  4. 내장 탐지 규칙과 파서, 데이터소스 수집 방법의 종류를 확인한다

A. Settings 둘러보기

왼쪽 메뉴에서 Settings를 누릅니다. 설정은 상단 메뉴에서 선택한 환경에 적용되고, 다섯 탭으로 나뉩니다. 값을 바꾸려면 카탈로그의 MANAGE 권한이 필요하고, 없으면 읽기 전용으로 보입니다. 탭마다 Save changes를 눌러야 적용됩니다.

탭설정하는 것기본값 (검증 환경에서 확인)
Environment환경 정보, 폴더, Lakewatch 관리자B
Detection rules탐지 규칙을 만들 때 고르는 범주(Detection categories)Static Signature, Fuzzy Signature, Behavioral, Statistical, Learning (AI/ML)
Datasources새 데이터소스 수집 파이프라인의 컴퓨팅 기본값(Performance optimized)—
AlertsAlert 그룹화 시간 창(Collation window), Alert 전송 대상전송 대상 Off
System errors시스템 오류 그룹화 시간 창, 시스템 오류 전송 대상전송 대상 Off

  • Detection categories: 규칙은 반드시 범주 하나를 골라야 합니다. 이 목록을 비워 두면 아무도 규칙을 만들 수 없습니다.

  • Performance optimized: 켜면 수집이 빠른 성능 최적화 컴퓨팅을, 끄면 표준 컴퓨팅을 씁니다. 표준 컴퓨팅은 비용이 낮지만 시작에 시간이 더 걸립니다.

  • Collation window: 열려 있는 Alert에 일치하는 보안 이벤트를 얼마 동안 계속 묶을지 정합니다. 단위는 Minutes, Hours, Days 중에서 고릅니다.

  • Alert destination: Alert를 받을 곳입니다. 목록은 jira, servicenow, tines, webhook이고 기본은 Off입니다. 설정 방법은 Alert 전송 대상 (opens in a new tab)을 참조하세요.

B. Environment 탭

구역할 수 있는 일
Details환경을 받치는 카탈로그(Backing catalog)와 환경을 쓸 수 있는 워크스페이스 확인
Folders폴더별 기본 용도(Default for)와 권한 확인. Add folder로 폴더 추가, Edit로 권한 변경, Delete로 삭제
Lakewatch administrators주체를 입력하고 Grant로 관리자 추가, Revoke로 회수
Create environment개발·운영 분리처럼 환경을 하나 더 만들 때 사용. 요건은 처음 설정할 때와 같습니다
  • 환경은 카탈로그가 바인딩된 워크스페이스에서만 쓸 수 있습니다. 다른 워크스페이스에서 열면 Environment unavailable이 표시됩니다.
  • Add folder로 새 폴더를 만들면 All account users가 Folder admin으로 들어갑니다. 모든 사용자가 그 폴더를 관리할 필요가 없으면 이 항목을 지우세요.
  • 폴더를 삭제하면 그 스키마와 안에 있는 Unity Catalog 객체(테이블, 볼륨 등)가 모두 영구 삭제됩니다. 폴더 안의 Lakewatch 리소스(데이터소스, 탐지 규칙)를 먼저 지워야 삭제할 수 있습니다.

C. 권한 그룹

Lakewatch UI에서는 개별 권한 대신 권한 그룹으로 접근을 줍니다. 폴더 권한 그룹은 폴더의 스키마에 권한을 부여하므로 폴더 안의 모든 데이터소스와 탐지 규칙에 적용됩니다.

권한 그룹부여 위치할 수 있는 일권한
Lakewatch admin카탈로그환경 전체 관리CREATE_RULE, CREATE_DATASOURCE, READ_METADATA, MANAGE, READ_SECURITY_DATA, UPDATE_SECURITY_DATA, SELECT, MODIFY, CREATE TABLE, CREATE SCHEMA, CREATE_SECRET
Folder admin폴더폴더 안 리소스와 권한 관리CREATE_RULE, CREATE_DATASOURCE, READ_METADATA, MANAGE, READ_SECURITY_DATA, UPDATE_SECURITY_DATA, SELECT, MODIFY, CREATE TABLE
Datasource manager폴더데이터소스 생성·관리CREATE_DATASOURCE, READ_METADATA, MANAGE, SELECT, MODIFY, CREATE TABLE
Detection rule manager폴더탐지 규칙 생성·관리, Alert 읽기CREATE_RULE, READ_METADATA, MANAGE, SELECT, MODIFY, CREATE TABLE, READ_SECURITY_DATA
Alert triage폴더Alert 읽기·갱신, 테이블 조회READ_METADATA, SELECT, READ_SECURITY_DATA, UPDATE_SECURITY_DATA

3단계 E에서 실제로 부여된 권한을 조회한 결과가 이 표와 일치했습니다.

Custom을 고르면 개별 권한을 직접 선택합니다. 화면의 이름과 권한은 아래와 같습니다.

화면 이름권한
Create datasourcesCREATE_DATASOURCE
Create detection rulesCREATE_RULE
Read detection rules/datasourcesREAD_METADATA
Manage resources and permissionsMANAGE
Read alertsREAD_SECURITY_DATA
Update alertsUPDATE_SECURITY_DATA
Read Lakewatch tablesSELECT
Modify Lakewatch tablesMODIFY
Create Lakewatch tablesCREATE TABLE

폴더의 용도에 맞지 않는 권한에는 안내가 붙습니다. 기본 데이터소스 폴더에서는 탐지 규칙·Alert 권한(Create detection rules, Read alerts, Update alerts) 위에 "Not recommended for the default datasource location"이, 기본 탐지 규칙 폴더에서는 Create datasources 위에 "Not recommended for the default detection rule location"이 표시됩니다.

D. 역할별로 접근 나누기

보안 팀은 보통 데이터를 수집하는 사람, 탐지 규칙을 만드는 사람, Alert를 처리하는 사람을 나눕니다. 공식 문서의 예시 구성은 그룹 네 개를 씁니다.

그룹역할부여
lakewatch-admins환경, 폴더, 접근 권한 관리환경의 Lakewatch admin
lakewatch-data-engineers데이터소스 온보딩과 유지datasources 폴더의 Datasource manager
lakewatch-detection-engineers탐지 규칙 작성과 튜닝detection 폴더의 Detection rule manager, datasources 폴더의 Custom(Read detection rules/datasources, Read Lakewatch tables)
lakewatch-analystsAlert 대기열 처리, 데이터 조회detection 폴더의 Alert triage, datasources 폴더의 Custom(Read detection rules/datasources, Read Lakewatch tables)

적용 순서는 다음과 같습니다.

순서작업누가어디서
1그룹 네 개를 만들고 구성원 추가계정 관리자계정 콘솔 User management > Groups
2lakewatch-admins를 관리자로 추가한 뒤 All account users 회수Lakewatch 관리자Settings > Environment > Lakewatch administrators
3폴더마다 Edit로 위 표의 권한 그룹 부여, All account users 제거Lakewatch 관리자Settings > Environment > Folders
4실행용 서비스 주체 설정 (권장)계정 관리자, Lakewatch 관리자계정 콘솔과 Unity Catalog
5Lakewatch administrators와 폴더의 Permissions 열 확인Lakewatch 관리자Settings > Environment

lakewatch-admins는 카탈로그 수준의 Lakewatch admin이 모든 폴더를 포함하므로 폴더 권한을 따로 줄 필요가 없습니다. 단계별 설명과 서비스 주체 설정은 Lakewatch 접근 제어 설정 (opens in a new tab)을 따르세요.

ℹ️

실습 참가자에게 줄 권한
진행자가 만든 환경에서 참가자가 미션을 수행한다면, 참가자 그룹에 실습 리소스가 들어 있는 폴더의 Detection rule manager(규칙 읽기·작성)와 Alert triage(Alert 갱신)를 줍니다. 실습 노트북은 자체 스키마(signal_dynamics_lab)에 리소스를 만들며, 이 스키마는 5단계 C에서 폴더로 직접 등록해야 합니다. 참가자 권한도 그 폴더에 줍니다.

E. 데이터를 넣기 전에 둘러보기

E1. Content library

Content library는 Databricks가 작성한 탐지 규칙 모음입니다. 검증 환경에는 규칙 74개가 있었고, 심각도, MITRE ATT&CK, 파서, 데이터소스로 걸러 볼 수 있습니다. Matching datasources 열은 그 규칙에 맞는 데이터소스가 환경에 있는지 보여 줍니다. 데이터소스가 없는 지금은 모두 비어 있습니다.

자세한 내용은 콘텐츠 라이브러리 (opens in a new tab)를 참조하세요.

E2. Parsers

Parsers에는 내장 파서와 직접 만든 파서가 함께 나옵니다. 검증 환경에는 내장(Built-in) 파서 123개가 있었습니다. 일부 파서에는 Lakeflow Connect 표시가 붙어 있습니다. Create parser로 사용자 지정 파서를 만듭니다.

E3. Add datasource

Datasources > Add datasource를 누르면 수집 방법을 고르는 화면이 열립니다.

구역항목
Managed connectors서비스 API에 연결하거나 파일·테이블·큐에서 로그를 수집합니다. 상위 커넥터로 Okta, AWS CloudTrail, Google Cloud, Microsoft 365, Atlassian이 나오고 Browse all로 전체를 봅니다
Custom & internal logsUnity Catalog table, Unity Catalog volume, Unity Catalog external location, Amazon S3, Amazon S3 with SQS notifications

실습 노트북은 볼륨에 놓인 파일을 읽는 데이터소스 다섯 개를 API로 만듭니다. 이 화면의 Unity Catalog volume에 해당하는 방식입니다. 화면에서 직접 만드는 절차는 데이터소스 생성 및 관리 (opens in a new tab)를 참조하세요.

완료 기준

  • Settings > Environment에서 관리자와 두 폴더의 권한이 의도한 주체로 표시됩니다
  • Detection rules 탭에 범주가 하나 이상 있습니다
  • 탐지 규칙에 쓸 웨어하우스가 Databricks SQL 2026.36 이상입니다 (1단계 B3)
