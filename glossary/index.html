용어 정리

용어 정리

이 가이드와 Lakewatch 화면에 나오는 용어를 영역별로 모았습니다. 제품 화면에 영문으로 보이는 이름은 영문 그대로 적고 뜻을 풀었습니다. 정의는 공식 문서 기준이며, 각 표의 "더 보기"에서 해당 문서로 이동합니다.

한눈에 보는 흐름

로그 한 줄이 Alert가 되기까지 거치는 순서입니다. 아래 표의 용어가 이 흐름의 어디에 해당하는지 먼저 보면 읽기 쉽습니다.

순서일어나는 일관련 용어
1로그 소스에서 원시 데이터를 읽어 옵니다데이터소스, 수집 방법, 원시 데이터
2파서가 원시 데이터를 열과 유형이 정해진 테이블로 바꿉니다파서, 파싱된 테이블, Observable
3탐지 규칙이 일정에 따라 파싱된 테이블을 SQL로 검사합니다탐지 규칙, 일정, 실행 창
4조건에 맞는 행마다 탐지 기록이 생깁니다Signal, 중복 제거
5관련된 탐지 기록이 조사 단위로 묶입니다Alert, Signal 그룹화
6분석가가 조사하고 판정을 남기거나 외부 도구로 내보냅니다상태, 분류, Triage with Genie, Alert 전송 대상

환경과 권한

용어뜻더 보기
환경 (Environment)Lakewatch에 등록한 Unity Catalog 카탈로그입니다. 격리된 Lakewatch 인스턴스이며, 카탈로그가 바인딩된 워크스페이스에서만 열립니다. 화면 위쪽의 환경 선택기에서 고릅니다접근 제어 모델 (opens in a new tab)
폴더 (Folder)환경 카탈로그 아래에 등록한 스키마입니다. 데이터소스와 탐지 규칙이 폴더 안에 놓이고, 폴더에 준 권한은 그 안의 모든 리소스에 적용됩니다접근 제어 모델 (opens in a new tab)
권한 그룹 (Permission group)역할에 맞춰 묶어 둔 Unity Catalog 권한 집합입니다. Lakewatch admin, Folder admin, Datasource manager, Detection rule manager, Alert triage가 있습니다역할과 기능 (opens in a new tab)
실행 주체 (Run as)데이터소스와 탐지 규칙의 예약 실행에 쓰이는 사용자 또는 서비스 주체입니다. 리소스를 만들 때 지정하며, 예약 실행은 이 주체의 권한으로 테이블에 접근합니다접근 제어 모델 (opens in a new tab)
탐지 웨어하우스탐지 규칙이 실행되는 SQL 웨어하우스입니다. 규칙마다 선택합니다탐지 웨어하우스 (opens in a new tab)

수집과 파싱

용어뜻더 보기
데이터소스 (Datasource)원시 보안 데이터를 읽고 파서로 처리해 Unity Catalog 테이블에 기록하는 파이프라인입니다. 수집 방법 하나와 파서 하나 이상을 결합합니다데이터소스 (opens in a new tab)
수집 방법 (Ingestion method)원시 데이터를 읽는 방식입니다. 클라우드 스토리지, 기존 테이블, API 커넥터 세 가지가 있습니다데이터소스 (opens in a new tab)
원시 데이터 (Raw data)수집 방법이 소스에서 읽어 온, 아직 파싱하지 않은 데이터입니다. 클라우드 스토리지 수집은 원본 레코드를 원시 테이블(raw table)에 먼저 저장합니다Lakewatch 소개 (opens in a new tab)
파서 (Parser)로그 소스의 출력 열, 유형, 이벤트 시각을 정의해 원시 데이터를 파싱된 테이블로 바꾸는 정의입니다. 내장 파서와 사용자 지정 파서가 있습니다파서 참조 (opens in a new tab)
파싱된 테이블 (Parsed table)파서가 기록하는 스키마화된 테이블입니다. 파서에서 선언한 필드에 더해 Lakewatch가 관리하는 lw_id, lw_meta, lw_observables 열이 붙습니다. 탐지 규칙과 쿼리의 대상입니다Lakewatch 소개 (opens in a new tab)
Observable (관측 대상)이벤트에서 뽑아낸 보안 관련 값입니다. IP 주소, 사용자 이름, 호스트 이름, 파일 해시 등이 있으며 lw_observables 열에 담깁니다. 소스가 달라도 같은 값으로 검색할 수 있게 해 줍니다파서 참조 (opens in a new tab)
Unmatched rows데이터소스에 연결한 어느 파서에도 맞지 않은 이벤트 수입니다. 이 이벤트는 파싱된 테이블에 기록되지 않습니다데이터소스 (opens in a new tab)

탐지

용어뜻더 보기
탐지 규칙 (Detection rule)일정에 따라 테이블을 SQL로 검사하는 규칙입니다. 조건에 맞는 결과 행마다 Signal을 만듭니다탐지 (opens in a new tab)
Content libraryDatabricks가 작성한 기본 제공 탐지 규칙 모음입니다. 규칙을 골라 가져오면(Import) 꺼진 상태의 사본이 만들어지고, 켜야 실행됩니다콘텐츠 라이브러리 (opens in a new tab)
일정 (Schedule)규칙이 실행되는 주기입니다. At least every(간격, 최소 5분) 또는 Exactly at(cron, UTC 기준)으로 정합니다. 데이터소스의 수집 일정과는 별개입니다탐지 규칙 관리 (opens in a new tab)
실행 창한 번의 실행이 검사하는 시간 범위입니다. SQL에 IN_TIMERANGE(time)을 쓰면 Lakewatch가 실행마다 범위를 넣어 줍니다. 시작 시각은 포함하고 끝 시각은 제외합니다탐지 규칙 작성 (opens in a new tab)
Extend lookback늦게 도착한 로그를 놓치지 않도록 실행 창의 시작을 앞당기는 규칙별 설정입니다탐지 규칙 작성 (opens in a new tab)
심각도 (Severity)규칙에 지정하는 위험 수준입니다. Alert 목록에서 심각도로 검색하고 필터할 수 있습니다탐지 규칙 관리 (opens in a new tab)
신뢰도 (Fidelity)규칙의 성숙도입니다. Development, Investigative, Medium, High가 있으며, 분석가가 Signal이 오탐일 가능성을 가늠하는 데 씁니다탐지 규칙 관리 (opens in a new tab)
요약 (Summary)Signal의 제목이 되는 필수 항목입니다. {source_ip}처럼 중괄호 안에 SQL 표현식을 넣어 이벤트 값을 채웁니다. Signal을 Alert로 묶는 기준에도 쓰입니다탐지 규칙 관리 (opens in a new tab)
Generate alerts규칙의 Signal이 새 Alert를 여는지 정하는 설정입니다. 꺼도 규칙은 계속 실행되어 Signal을 만듭니다탐지 규칙 관리 (opens in a new tab)

Signal과 Alert

용어뜻더 보기
Signal (시그널)탐지 규칙의 조건이 맞았을 때 생기는 탐지 기록입니다. 무엇이 탐지되었는지, 언제 일어났는지, 어떤 엔티티가 관련되었는지를 담습니다. 원본 로그가 아니며, 만들어진 뒤에는 바뀌지 않습니다Signal (opens in a new tab)
엔티티 (Entity)Signal과 Alert에 연결되는 대상입니다. 사용자, IP 주소, 호스트처럼 조사할 때 따라가는 주체와 리소스를 가리킵니다Signal (opens in a new tab)
중복 제거 (Deduplication)같은 규칙에서 출력 행 전체가 같은 Signal이 다시 나오면 건너뛰는 동작입니다. 규칙마다 기본으로 켜져 있습니다Signal (opens in a new tab)
Alert (경보)조사하기 쉽도록 Lakewatch가 관련 Signal을 자동으로 묶은 단위입니다. 분석가가 담당자를 정하고, 분류하고, 해결될 때까지 추적합니다Alert (opens in a new tab)
Signal 그룹화규칙, 규칙 버전, 요약이 같은 Signal을 하나의 Alert로 묶는 동작입니다. 중복 제거 다음 단계에서 일어납니다Alert (opens in a new tab)
그룹화 시간 창 (Collation window)Alert 하나가 열린 채로 Signal을 모으는 기간입니다. 기본 1시간이며 환경별로 Settings에서 바꿉니다Alert (opens in a new tab)
상태 (State)Alert의 처리 단계입니다. Open, In progress, Mitigated, Resolved, Duplicate가 있습니다Alert (opens in a new tab)
분류 (Classification)조사 결과에 대한 판정입니다. True positive(실제 위협), Benign positive(탐지는 맞지만 정상 활동), False positive(잘못된 탐지)가 있습니다Alert (opens in a new tab)
Alert 전송 대상 (Alert destination)Alert를 내보내는 외부 시스템입니다. Jira, ServiceNow, Tines, 웹훅을 지원합니다Alert 전송 대상 (opens in a new tab)
시스템 오류 (System error)데이터소스나 탐지 규칙의 실행 실패, 구성 문제를 알리는 운영 오류입니다. 보안 Alert와 별도로 추적합니다시스템 오류 (opens in a new tab)
Query보안 데이터를 SQL로 직접 조회하는 화면입니다. 날짜 선택기, Refinements(다시 실행하지 않는 필터·정렬·집계), 행 상세 보기를 제공합니다쿼리 (opens in a new tab)

Genie

용어뜻더 보기
Genie CodeLakewatch 화면 전반에 들어 있는 AI 어시스턴트입니다. SQL 작성, 탐지 규칙 작성, 데이터소스 탐색을 자연어로 돕습니다Genie (opens in a new tab)
Triage with GenieAlert 화면에서 Genie가 조사 계획을 세우고, 근거를 조회하고, 판정을 제안하는 기능입니다. Alert를 바꾸기 전에 분석가의 승인을 받습니다Genie (opens in a new tab)
Create with Genie탐지 규칙을 만드는 화면에서 탐지 내용을 설명하면 Genie가 SQL, 요약, MITRE ATT&CK 매핑을 채워 주는 기능입니다Genie (opens in a new tab)
Genie Agents여러 단계에 걸친 심층 조사에 쓰는 Agent입니다. 파싱된 테이블과 위협 인텔리전스 테이블을 연결해 위협 헌팅에 씁니다Genie (opens in a new tab)

보안 일반 용어

Lakewatch에만 있는 용어는 아니지만 가이드와 화면에 자주 나옵니다.

용어뜻
SIEM (Security Information and Event Management)보안 정보·이벤트 관리. 여러 시스템의 로그를 모아 위협을 탐지하고 조사하는 체계입니다
MITRE ATT&CK공격자의 전술(Tactic, 목적)과 기법(Technique, 수단)을 정리한 공개 분류 체계입니다. T1110.003처럼 번호로 표기하며, 탐지 규칙마다 매핑을 붙입니다
IOC (Indicator of Compromise)침해 지표. 악성으로 알려진 IP 주소, 도메인, 파일 해시 같은 값입니다
위협 헌팅 (Threat hunting)Alert를 기다리지 않고 가설을 세워 데이터에서 공격 흔적을 직접 찾는 활동입니다
분류, 트리아지 (Triage)Alert를 살펴 실제 위협인지 판단하고 우선순위와 처리 방향을 정하는 일입니다
런북 (Runbook)특정 Alert를 받았을 때 따라 할 조사·대응 절차입니다. Content library 규칙에 포함된 경우가 있습니다

헷갈리기 쉬운 것

질문답
데이터소스와 파서를 연결하면 탐지 규칙도 바로 적용되나요?아닙니다. 데이터소스와 파서는 로그를 파싱된 테이블에 기록하는 데까지만 합니다. 탐지 규칙은 따로 만들거나 Content library에서 가져와 켜야 실행됩니다
Content library를 열면 규칙이 실행되나요?아닙니다. 가져온 규칙은 꺼진 상태의 사본입니다. 규칙이 읽는 테이블이 수집 중인 데이터와 맞는지 확인한 뒤 켜고 일정을 정합니다
데이터소스 일정과 탐지 규칙 일정은 같은 것인가요?다릅니다. 데이터소스 일정은 수집·파싱 주기이고, 규칙 일정은 탐지 SQL의 실행 주기입니다. 이벤트가 탐지되기까지 걸리는 시간은 두 일정에 함께 좌우됩니다
Signal과 Alert는 어떻게 다른가요?Signal은 규칙의 결과 행 하나에 대한 탐지 기록이고, Alert는 관련 Signal을 묶은 조사 단위입니다. 분석가가 담당하고 판정을 남기는 대상은 Alert입니다
Alert와 시스템 오류는 어떻게 다른가요?Alert는 보안 탐지 결과이고, 시스템 오류는 Lakewatch 자체의 실행·구성 문제입니다. 서로 다른 목록에서 추적합니다
상태와 분류는 어떻게 다른가요?상태는 처리가 어디까지 진행됐는지이고, 분류는 조사 결과가 무엇이었는지입니다. 정상 활동을 올바르게 탐지한 경우는 False positive가 아니라 Benign positive입니다
화면의 시각은 어느 시간대인가요?Query에서는 UTC 또는 기기에서 감지한 현지 시각을 고를 수 있습니다. cron 일정(Exactly at)은 UTC 기준입니다
