3. 환경 만들기

3단계 - 환경 만들기

Welcome to Lakewatch 설정으로 Lakewatch 환경을 만듭니다. 환경은 Unity Catalog의 카탈로그 하나이고, 그 안의 폴더(스키마) 두 개에 데이터소스와 탐지 규칙이 들어갑니다. 누구나 관리자가 되는 Recommended configuration과, 카탈로그 이름과 권한을 미리 정하는 Custom configuration 중 하나를 고릅니다.

근거 문서: 워크스페이스용 Lakewatch 설정 (opens in a new tab)

학습 목표

  1. 환경, 폴더, 관리자가 Unity Catalog의 무엇에 대응하는지 설명한다
  2. Recommended와 Custom 구성의 차이를 알고 상황에 맞게 고른다
  3. Custom 구성으로 카탈로그 이름, 폴더 권한, 관리자를 정해 환경을 만든다
  4. 설정이 만든 카탈로그·스키마·권한을 확인한다

A. 개념 잡기

LakewatchUnity Catalog내용
환경 (Environment)카탈로그격리된 Lakewatch 인스턴스. 이 워크스페이스에서만 접근합니다
폴더 (Folder)스키마데이터소스·탐지 규칙 같은 리소스의 묶음. 폴더에 준 권한이 그 안의 모든 리소스에 적용됩니다
Lakewatch admin카탈로그 권한 묶음환경과 모든 폴더·데이터소스·탐지 규칙을 관리합니다

설정은 워크스페이스에서 한 번만 합니다. 설정을 진행하려면 SQL 웨어하우스가 선택되어 있어야 합니다(1단계 B2).

B. 구성 방식 고르기

  1. Welcome to Lakewatch 화면에서 Get started with Lakewatch를 누릅니다. 아래에 Configuration 구역이 열립니다.
  2. Recommended configuration이 기본으로 선택되어 있습니다.

Recommended configurationCustom configuration
카탈로그새 카탈로그 lakewatch를 만듭니다새 카탈로그 이름을 정하거나 기존 카탈로그를 고릅니다
폴더datasources, detection이름과 권한을 바꿀 수 있습니다
관리자모든 계정 사용자(All account users)가 Lakewatch admin지정한 주체만
폴더 권한모든 계정 사용자가 두 폴더의 모든 권한주체별로 권한 그룹을 지정
필요한 권한CREATE CATALOGCREATE CATALOG, 또는 기존 카탈로그의 MANAGE와 CREATE SCHEMA
맞는 상황혼자 쓰는 평가용 워크스페이스여러 사람이 쓰는 워크스페이스, 운영 환경, 기존 카탈로그 등록
⚠️

Recommended 구성은 모든 계정 사용자를 관리자로 만듭니다
Recommended configuration은 워크스페이스를 쓸 수 있는 모든 사람에게 환경 관리 권한을 줍니다. Lakewatch가 무엇이든 만들기 전에 카탈로그, 폴더, 접근 권한을 정하려면 먼저 Custom configuration을 선택하세요. 접근 권한은 설정 뒤에도 바꿀 수 있습니다.

혼자 쓰는 워크스페이스라면 Recommended 그대로 Create를 눌러도 됩니다. 이 가이드는 여러 사람이 쓰는 워크스페이스에서 확인했으므로 아래 C–E의 Custom 구성으로 진행합니다.

C. Custom configuration

Custom configuration을 누르면 다섯 항목이 표로 나옵니다. 연필 아이콘이 있는 항목은 편집할 수 있고, 편집한 내용은 설정 초안에만 저장됩니다. Create를 누르기 전에는 아무것도 만들어지지 않습니다.

항목기본값설명
EnvironmentNew Catalog: lakewatch환경을 받치는 카탈로그
Workspace현재 워크스페이스환경과 카탈로그는 이 워크스페이스에서만 접근합니다 (편집 불가)
Datasource folderdatasources · All account users데이터소스의 기본 위치
Detection & Alerts folderdetection · All account users탐지 규칙과 Alert의 기본 위치
AdminsAll account users환경과 리소스, 권한을 관리할 수 있는 주체

데이터소스와 탐지 규칙은 서로 다른 폴더에 두세요. 한 폴더를 같이 쓰면 두 리소스의 읽기·편집 권한을 따로 줄 수 없습니다.

C1. 카탈로그 이름 정하기

  1. Environment 행의 연필 아이콘을 누릅니다. Edit environment 창이 열립니다.
  2. Create a new catalog을 선택한 채로 Catalog name에 이름을 입력합니다. 검증 환경에서는 lakewatch_hol을 썼습니다.
  3. Done을 누릅니다.

  • 새 카탈로그는 기본 스토리지 위치를 씁니다("The catalog will use the default storage location."). 직접 소유한 클라우드 스토리지 버킷에 관리형 스토리지 위치를 둔 카탈로그를 쓰려면 Use an existing catalog으로 그 카탈로그를 고릅니다.
  • 환경을 받치는 카탈로그는 나중에 바꿀 수 없습니다.
  • 카탈로그 이름은 메타스토어 안에서 유일해야 합니다. 같은 리전의 워크스페이스들이 메타스토어를 함께 쓰면 lakewatch라는 이름을 다른 워크스페이스가 이미 쓰고 있을 수 있습니다. 그때는 다른 이름을 입력합니다.
  • CREATE CATALOG가 없으면 Use an existing catalog을 선택하고, MANAGE와 CREATE SCHEMA를 가진 카탈로그를 고릅니다. 이미 Lakewatch 환경인 카탈로그는 고를 수 없습니다.

C2. 관리자 지정하기

  1. Admins 행의 연필 아이콘을 누릅니다. Edit Lakewatch administrators 창이 열립니다.
  2. Principal 입력란에 관리자로 지정할 사용자나 그룹 이름을 입력해 목록에서 고르고 Add를 누릅니다.
  3. All account users 행의 Remove를 누릅니다.
  4. Done을 누릅니다.

⚠️

관리자를 먼저 추가하고 나서 All account users를 지우세요
설정에는 관리자가 최소 한 명 있어야 합니다. 새 관리자를 추가하기 전에 All account users를 지우면 관리자가 없는 상태가 됩니다. 주체로는 계정 사용자, 계정 그룹, 서비스 주체를 쓸 수 있습니다.

C3. 폴더 권한 정하기

두 폴더에 같은 절차를 반복합니다.

  1. Datasource folder 행의 연필 아이콘을 누릅니다. Configure datasource folder 창이 열립니다. 폴더 이름도 여기서 바꿀 수 있습니다.
  2. Add principal을 누릅니다.
  3. Principal에 주체를 입력해 고르고, Select permission groups에서 권한 그룹을 선택합니다. 권한 그룹을 고르면 아래 Individual permissions의 해당 항목이 함께 체크됩니다.
  4. Add를 누릅니다.
  5. 기본으로 들어 있는 All account users 행의 Remove를 누르고 Done을 누릅니다.
  6. Detection & Alerts folder에도 1–5를 반복합니다.

폴더마다 고를 수 있는 권한 그룹이 다릅니다. 그 폴더에 담기는 리소스에 맞지 않는 권한 그룹은 목록에 나오지 않습니다.

폴더고를 수 있는 권한 그룹
Datasource folderFolder admin, Datasource manager, Custom
Detection & Alerts folderFolder admin, Detection rule manager, Alert triage, Custom

권한 그룹별 권한은 4단계에 정리했습니다. 폴더 권한은 더해지는 방식이며("Access is additive"), 폴더에 준 권한은 그 폴더의 모든 데이터소스와 탐지 규칙에 적용됩니다.

검증 환경에서는 두 폴더 모두 진행자 한 명만 Folder admin으로 두었습니다. 실습 참가자가 있으면 참가자 그룹을 여기서 추가하거나, 설정 뒤 Settings > Environment에서 추가합니다.

D. 환경 만들기

  1. 요약 표에서 값이 의도대로 바뀌었는지 확인합니다.

  2. Create를 누릅니다. "Creating your Lakewatch environment…"가 표시됩니다.

  3. 설정이 끝나면 Overview 페이지로 넘어갑니다. 검증 환경에서는 약 10초가 걸렸습니다.

Lakewatch는 카탈로그와 스키마를 만들고, 이를 환경과 폴더로 등록하고, 권한을 부여합니다. 도중에 실패하면 Create를 다시 누르세요. 선택한 값은 유지됩니다.

주소는 /lakewatch/<catalog>/home 형태가 됩니다. 왼쪽 메뉴는 조사 영역(Overview, Alerts, System errors, Query, Genie)과 구성 영역(Datasources, Detection rules, Content library, Parsers, Settings)으로 나뉩니다.

완료 기준: Overview 페이지가 열리고, Environment, workspace and compute 메뉴의 Environment에 방금 만든 카탈로그 이름이 보입니다.

E. 만들어진 것 확인하기

SQL Editor나 Catalog Explorer에서 설정이 만든 객체를 확인합니다.

SHOW SCHEMAS IN <catalog>;
SHOW GRANTS ON CATALOG <catalog>;
SHOW GRANTS ON SCHEMA <catalog>.datasources;

검증 환경(lakewatch_hol)에서 확인한 결과입니다.

객체내용
카탈로그격리 모드 ISOLATED, 현재 워크스페이스에만 바인딩(읽기·쓰기), Default Storage 사용
스키마 __lakewatch내부 스키마. 소유자는 사용자가 아니라 UUID로 표시되는 주체입니다. signals·system_events 뷰와 시크릿이 여기에 들어갑니다
스키마 datasources, detection폴더. 소유자는 설정한 사용자
스키마 default카탈로그를 만들 때 자동 생성되는 기본 스키마
대상주체부여된 권한
카탈로그지정한 관리자 (Lakewatch admin)CREATE_DATASOURCE, CREATE_RULE, CREATE_SCHEMA, CREATE_SECRET, CREATE_TABLE, MANAGE, MODIFY, READ_METADATA, READ_SECURITY_DATA, SELECT, UPDATE_SECURITY_DATA
카탈로그account usersUSE_CATALOG, USE_SCHEMA
폴더 스키마 2개지정한 주체 (Folder admin)CREATE_DATASOURCE, CREATE_RULE, CREATE_TABLE, MANAGE, MODIFY, READ_METADATA, READ_SECURITY_DATA, SELECT, UPDATE_SECURITY_DATA, USE_SCHEMA
폴더 스키마 2개account usersUSE_SCHEMA

모든 계정 사용자에게 주어지는 USE CATALOG와 USE SCHEMA는 Custom 구성에서도 똑같이 부여됩니다. 폴더까지 도달할 수 있게 하는 통과 권한일 뿐, 폴더 안의 내용을 보거나 바꿀 수는 없습니다. __lakewatch 스키마에 시크릿을 만들 수 있게 하려는 것입니다.

ℹ️

환경은 Lakewatch에서 지울 수 없습니다
환경을 없애려면 Unity Catalog에서 그 카탈로그를 삭제(DROP CATALOG)합니다. 카탈로그를 삭제하면 폴더를 포함한 모든 스키마와 내용이 영구 삭제됩니다.
