1. 사전 요건 확인

1단계 - 사전 요건 확인

Lakewatch를 켜기 전에 워크스페이스가 네 가지 요건(Unity Catalog, 서버리스 SQL 웨어하우스, 서버리스 작업 컴퓨팅, AI 기능)을 갖췄는지 확인합니다. 하나라도 빠지면 설정이 멈추거나 일부 화면이 비어 보입니다.

근거 문서: Lakewatch 사전 요구 사항 (opens in a new tab)

학습 목표

  1. Lakewatch가 요구하는 워크스페이스 기능 네 가지를 설명한다
  2. Lakewatch UI가 쓰는 SQL 웨어하우스를 확인하고 서버리스 웨어하우스로 바꾼다
  3. 탐지 규칙을 실행할 웨어하우스의 Databricks SQL 버전을 확인한다

B. SQL 웨어하우스

B1. 서버리스여야 하는 이유

Lakewatch는 데이터소스 이벤트 수 같은 일부 데이터를 Databricks Default Storage에 보관하는데, 이 스토리지는 서버리스 컴퓨팅만 읽을 수 있습니다. 클래식·Pro 웨어하우스를 쓰면 이 데이터가 로딩되지 않아, 예를 들어 Datasources 페이지에 이벤트 수가 표시되지 않습니다.

Lakewatch는 웨어하우스를 만들어 주지 않습니다. 접근할 수 있는 웨어하우스 중 아래 순서로 처음 해당하는 것을 씁니다.

  1. 브라우저에서 마지막으로 선택한 웨어하우스
  2. 실행 중인 웨어하우스
  3. 사용할 수 있는 첫 번째 웨어하우스 (Lakewatch가 시작합니다)
⚠️

웨어하우스 유형은 자동으로 확인되지 않습니다
Lakewatch는 웨어하우스를 고를 때 유형을 확인하지 않으므로 클래식·Pro 웨어하우스가 선택될 수 있습니다. 워크스페이스에 웨어하우스가 여러 개 있으면 아래 B2에서 서버리스 웨어하우스를 직접 고르세요.

B2. 웨어하우스 확인·변경

  1. Lakewatch 화면 오른쪽 위의 Environment, workspace and compute 아이콘(원통 모양)을 누릅니다.
  2. Compute 아래에 표시된 웨어하우스를 확인합니다. 다른 웨어하우스로 바꾸려면 그 항목을 눌러 서버리스 웨어하우스를 고릅니다.

위 화면은 환경을 만들기 전이라 Environment가 No environment selected로 나옵니다. 설정은 웨어하우스가 선택되어 있어야 진행되고, 그 웨어하우스로 카탈로그를 초기화합니다. 쿼리 페이지에는 이 선택기가 없고 자체 웨어하우스 선택기가 있습니다.

Lakewatch를 아직 켜지 않았다면 이 메뉴는 2단계를 마친 뒤에 볼 수 있습니다. 지금은 SQL Warehouses 페이지에서 서버리스 웨어하우스가 있는지만 확인하세요.

B3. 탐지 웨어하우스 버전

탐지 규칙은 규칙마다 지정한 SQL 웨어하우스에서 실행되고, 그 웨어하우스는 Databricks SQL 2026.36 이상이어야 합니다. Lakewatch는 채널 설정이 아니라 웨어하우스가 실제로 실행 중인 버전을 확인합니다.

해당 웨어하우스에서 아래 쿼리를 실행해 버전을 확인합니다.

SELECT current_version().dbsql_version;

검증 환경의 Serverless Starter Warehouse는 2026.46을 반환했습니다(2026-11-23).

자세한 내용은 탐지 웨어하우스 설정 (opens in a new tab)을 참조하세요.

C. 서버리스 작업 컴퓨팅

2024년 12월 16일 이후에 만든 계정은 서버리스 컴퓨팅이 자동으로 켜져 있습니다. 그보다 오래된 계정은 계정 관리자가 계정 콘솔에서 직접 켜야 합니다.

  1. 계정 관리자로 Accounts Console에 로그인합니다.
  2. Settings > Feature enablement로 이동합니다.
  3. Serverless compute를 찾아 켭니다. 약관 동의를 요청하면 동의합니다.
  4. 설정이 반영될 때까지 1–2분 기다린 뒤 Lakewatch를 다시 엽니다.
⚠️

워크스페이스의 같은 이름 설정과 혼동하지 마세요
워크스페이스 수준 Previews 페이지의 Serverless compute 설정은 접근 관리와 속도 제한을 다루는 별개 항목입니다. Lakewatch에 필요한 것은 계정 콘솔의 계정 수준 설정입니다.

D. AI 기능

Genie 기능에 어떤 모델이 쓰이는지, 기능을 쓸 수 있는지는 워크스페이스의 AI 설정(파트너 기반 AI 기능 포함)에 따라 달라집니다. 현재 요건은 Databricks AI assistive features (opens in a new tab)에서 확인하세요. 필요한 설정을 켤 수 없으면 담당 어카운트팀에 문의하세요.

ℹ️

검증 환경에서 확인한 범위
검증 워크스페이스에서 Lakewatch 환경 생성과 Settings, Content library, Parsers 화면이 동작하는 것을 확인했습니다. Genie 기능(Alert 분류, 규칙 생성)도 동작했습니다(8단계, 9단계).

E. 설정 담당자의 권한

환경을 만드는 사람은 아래 둘 중 하나가 필요합니다.

  • 메타스토어의 CREATE CATALOG: 새 카탈로그로 환경을 만듭니다. Recommended configuration은 새 카탈로그를 만들므로 이 권한이 있어야 합니다.
  • 기존 카탈로그의 MANAGE와 CREATE SCHEMA: 그 카탈로그를 환경으로 등록합니다. Custom configuration에서만 됩니다.

Unity Catalog가 자동으로 활성화된 워크스페이스에서는 워크스페이스 관리자가 기본으로 CREATE CATALOG를 갖습니다. 그렇지 않으면 메타스토어 관리자에게 요청하세요.

권한이 없으면 설정 화면이 알려 줍니다. CREATE CATALOG가 없으면 Get started with Lakewatch를 누른 뒤 Use an existing catalog가 표시되고 Recommended 구성의 Create를 쓸 수 없습니다. 등록할 수 있는 카탈로그도 없으면 Ask an administrator to set up Lakewatch가 표시됩니다(설정 화면이 표시될 때 (opens in a new tab)).

검증 환경에서는 워크스페이스 관리자 그룹에 CREATE_CATALOG가 부여되어 있어 새 카탈로그로 진행했습니다. 권한이 없을 때의 화면은 직접 확인하지 않았습니다.

완료 기준

  • 서버리스 SQL 웨어하우스가 하나 이상 있고, 버전이 2026.36 이상입니다
  • 계정에 서버리스 컴퓨팅이 켜져 있습니다
  • 환경을 만들 사람이 CREATE CATALOG, 또는 대상 카탈로그의 MANAGE와 CREATE SCHEMA를 갖고 있습니다
